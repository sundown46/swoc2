# P1 plan - live picture MVP

Status: draft for Leon (2026-10-03). Scope and acceptance criteria are in `ROADMAP.md` (P1); this
file only orders the work. Each milestone is one or a few PRs; milestones build on each other in
this order, but UI and backend work inside a milestone can run in parallel. Requirement IDs in
brackets.

Prerequisites from P0 that must be merged first: #7 (realtime transports, CSRF for the SPA),
#8 (plugin SDK skeleton).

## M1 - Persistence, audit, API docs

- PostgreSQL + PostGIS + TimescaleDB in `docker-compose.dev.yml`; Flyway migrations; Testcontainers
  for integration tests (ADR 0012).
- `audit` module: who/what/when/before/after for every state change, queryable (AUTH-005, ADM-006
  backend). Replaces the interim `audit.*` log lines from P0.
- OpenAPI generation for the REST API (API-001, open from P0) - **decision D1**.
- Security headers incl. CSP (part of GEN-015) - early, so every later page is built under the CSP.
- Instance settings store: sender ID, own position, aging defaults, debug console flags (ADM-003,
  SDX-004 backend).

## M2 - Domain core: units, coordinates, picture store

- `swoc2-domain`: units, angles, geodesy (GeographicLib), MGRS (NGA) with exhaustive tests; same
  libraries in `frontend/packages/units` incl. parsing of messy pasted coordinates (MAP-016/017
  foundation, CLAUDE.md principle 5).
- Canonical `Contact` model (ARCHITECTURE §5.1), identity `(connection, sourceSystem, track)`
  (PIC-009), multiple sources per object (PIC-008).
- In-memory picture store indexed by MGRS cell, aging stale/delete per connection (PIC-001,
  PIC-004, MAP-019), operator override layer persisted in the DB (PIC-003 backend), wipe with audit
  (PIC-005), classification of displayed data (GEN-011 backend).
- Load test harness (external tool, not product) for NFR-003: 100k contacts / 10k updates/s.

## M3 - SEDAP-Express connections

- `ConnectionType` SPI in `swoc2-plugin-api` (connection types are pluggable, CON-006) - extends
  the P0 SPI, `needs-review`.
- TCP client/server, UDP unicast/multicast, MQTT (SDX-002) - **decision D2** (MQTT client
  library). Lifecycle, backoff, isolation per connection (CON-003), metrics/health (CON-002),
  HEARTBEAT -> connection health (SDX-005).
- Router: loop prevention + dedup cache (CON-005), message numbering per type (SDX-004), OWNUNIT
  routing table for commands (CON-007).
- Mapping CONTACT/OWNUNIT -> picture (SDX-005); TEXT -> chat store (SDX-006).
- Debug tap for the debug console (DBG-001 backend).
- `tools/sedap-sender`: dev simulator that plays scenarios over TCP/UDP/MQTT; Mosquitto in the dev
  compose.

## M4 - Realtime picture topics

- Picture topics on the P0 realtime protocol: viewport subscription, snapshot + deltas, 2 Hz
  batching, only contacts in/near the viewport, MGRS aggregates above a threshold (ARCHITECTURE §6;
  aggregation display itself is MAP-014/P2, the server side is needed earlier for Canvas mode).
- NFR-002 latency measurement (500 contacts / 1 Hz / 20 sessions).

## M5 - App shell

- Mantine theme with light/dark tokens, switchable per user (GEN-008); dockview layout with
  dockable/minimisable panels (MAP-001); Zustand + TanStack Query; zod at every boundary.
- Per-user settings persisted server-side - view, layers, units, symbols, panel layout, theme,
  forced transport (AUTH-004, RNM-001 setting).
- Classification banner (GEN-011), secure-context degradation helpers (GEN-012), readable error
  handling (GEN-009).
- Frontend SDK grows: routes, panels in dockview, settings sections, admin pages (ADM-011).

## M6 - Map

- OpenLayers map with the P0 symbol atlas; bundled offline basemap - **decision D3**; base layers
  vs. overlays with per-user opacity (MAP-005/006); layer tree source type -> connection (MAP-002).
- Symbol settings (MAP-007), labels with decluttering - measured with the Spike A page (MAP-008),
  stale styling (MAP-019), source shown in tooltip (MAP-003).
- Hook/select incl. touch, long-press, select mode (MAP-010/011) via a CPU spatial index (ADR 0018).
- Own position, range/bearing, distance line (MAP-012/013); tool framework + measure tool
  (MAP-021, TLS-001/003); coordinate input component (MAP-017).

## M7 - Panels

- Contact list (PIC-002), CAC with override edits for Operators (PIC-003).
- Chat panel as an **internal plugin** on the SDK (CLAUDE.md principle 3): badge counter, dock /
  minimise, broadcast or recipient, SWOC2 user audited (CHT-001..003).
- Debug console with filter/pause/copy, enable globally/per role (DBG-001/002).

## M8 - Admin dashboard

- Connection manager with forms generated from JSON Schema, test before save (CON-001/002, ADM-002).
- Instance settings UI (ADM-003), wipe (ADM-005), audit viewer (ADM-006), system health incl.
  transport mix (ADM-009).
- Users and invites via the Keycloak Admin REST API (AUTH-003, ADM-001).
- WMS/WMTS wizard with GetCapabilities parsing and preview (MAP-004, ADM-004); offline tile
  package upload (MAP-006) - **decision D4**.

## M9 - Deployment and hardening

- `bundled-keycloak` profile under `{base}/auth`, fully offline (AUTH-008); realm-per-instance guide
  in `deploy/README.md` (AUTH-007).
- Built-in TLS: provided files or self-signed (GEN-013).
- Rate limiting, admin CIDR allowlist (trusted-proxy aware), session idle/absolute timeout
  (GEN-015).
- LXC/systemd guide (GEN-006), restricted-network check of everything with WS blocked (RNM-001),
  TESTING.md Phase 1 section per acceptance bullet.

## Decisions needed from Leon

| # | Question | Recommendation |
|---|---|---|
| D1 | OpenAPI generation (API-001): add `springdoc-openapi` (framework-level dependency)? | Yes - the standard for Spring; served at `/api/openapi.json` + Swagger UI only for admins/dev. |
| D2 | MQTT client for SDX-002 | **HiveMQ MQTT Client** (Apache-2.0, actively maintained, async, MQTT 3.1.1 + 5). Alternative: Eclipse Paho (what the reference library uses; the v5 client is maintained less actively). |
| D3 | Bundled offline basemap (MAP-006) | **Natural Earth** 1:50m land/coastline/borders (public domain), bundled as compact vector data, styled with theme tokens - works without any tile server. |
| D4 | Offline tile packages (MAP-006) | Support **PMTiles** first (single file, served by our backend via HTTP range requests, no extra server dependency); MBTiles later via `sqlite-jdbc` if needed. |
| D5 | Rate limiting (GEN-015) | Small own token bucket (single backend replica, ADR 0010) instead of adding Bucket4j. |

Everything else uses what CLAUDE.md already fixes (Mantine, dockview, Zustand, TanStack Query,
zod, PostgreSQL/PostGIS/TimescaleDB, Flyway, Testcontainers, GeographicLib, NGA MGRS).
